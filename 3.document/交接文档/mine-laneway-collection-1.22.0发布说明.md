# 矿井巷道采集技能 1.22.0

本次把原始数据采集与巷道判断拆开。

完整点采集：

- `collect.mjs points` 保留所有具有圆圈、编号和可解析文字的点，不再因为暂无同色双线候选而删除。
- 每个点记录 `same_color_corridor_ids` 和 `boundary_status`；缺少标高时保留空值。
- 直接支持 `ZB 1017.534`、`F13 962.373` 等编号与标高组合。
- 真实 `银二井上下对照图` 回归从 226 个点增加到 624 个点，其中 601 个有标高；405 个暂时未匹配同色双线候选的点仍完整保留。

大模型成巷：

- `model-packet.mjs` 把完整点清单和同色双线候选压缩成必要数据：点 ID、编号、标高、后缀、颜色、候选巷道、边界端点、handle 和几何质量。
- 真实图模型数据包为约 127 KB，使用字段说明和紧凑数组编码，避免单个事件超过 256 KiB。
- 大模型只能从同色、几何质量有效的 corridor 中选择点和排序。
- `materialize-lane-plan.mjs` 校验模型计划中的 corridor、点归属、重复使用和颜色，再生成最终巷道 JSON。
- `validate-lanes.mjs` 继续检查最终块是否含两条边线、编号、标高、来源和有效几何。

真实图自动回归中，按紧凑数据包选择完整点并排点后生成 47 条巷道，检查器结果为 47/47 有效。该回归只验证数据流和几何约束，不代表完成业务复核。

限制：

- 未被有效同色双线候选覆盖的点保留在点清单中，但不会自动生成正式巷道。
- 严格几何校验优先保证边界可信度，复杂交叉与灰区仍须人工复核。
