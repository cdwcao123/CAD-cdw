# 巷道插件：需求与现状（一页纸）

## 一、你的需求
1. 上传**未采集的原始图纸**（采掘工程平面图），自动画出巷道；
2. 导出 **JSON**，能导入 MAS Cloud CAD 生成采集图。

## 二、达成情况
| 需求 | 状态 | 说明 |
| --- | --- | --- |
| 上传原始 DWG/DXF 并自动识别 | ✅ 可用 | 3~4 万条线划，2~4 秒出结果 |
| 导出 JSON（MAS 字段） | ✅ 可用 | 25 字段与 `导出巷道数据.json` 一致；纯 ASCII 转义，GBK 读取不乱码 |
| 形状与人工一致 | ❌ **未达标** | 实测：98 条真值中，≤10 m 命中 **6 条（6%）** |

## 三、为什么形状对不上（已定位）
MAS 的巷道模型是：**导线点串成路径 + 每个点左右半宽**，两条帮线由系统按半宽生成（真值 JSON 里 `border_line_points` 只有 3 段，`traverse_point_array` 每点带 `left_side/right_side=2.0`）。

插件现在是**从线划反推**：双线配对取中线、配不上就单线推断、断点按容差续接。三条路径都可能与人工点选的路径不同，所以逐条比对只有 6% 命中；中位偏移仅 7/14 m，说明不是坐标问题，而是**走的不是同一条路径**。

## 四、正确的做法（下一步开发）
“导线点建图”：
1. 识别图上的**导线点圆圈**（实测半径 0.4 / 0.75 两种）；
2. 以导线点为**节点**，沿巷道线划连接相邻点，形成**图**；
3. 每条边 = 一条巷道段；顶点即导线点（`point_name`、`point_order`）；
4. 半宽 = 该处两帮间距的一半；
5. 输出 JSON → MAS 渲染，帮线/圆圈/标高由系统生成，**形状必然一致**。
